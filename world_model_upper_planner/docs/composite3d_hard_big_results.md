# 规模扩大训练结果（2026-09-07 第二轮）

第二轮按计划同时放大了下层与上层的训练规模与模型容量，目标是检验"绝对完成率低"
是否由训练量/容量不足造成。

## 改动与训练规模（相对第一轮）

| 项 | 第一轮 | 第二轮 |
|---|---|---|
| 下层 z 课程 | ±4 cm | **±6 cm** |
| 下层迭代 × 环境 | 200 × 2048 | **1000 × 2048** |
| 上层数据（转移 / 交互） | 335k / 8.2M | **671k / 16.4M** |
| 上层模型容量 | 256 / 64 / 64 | **512 / 128 / 128** |

## 结论（如实）

1. **下层明显进步**：±6 cm、0 跌倒、误差更小——说明下层训练规模扩大有效。
2. **上层绝对完成率没有提升**（8/64 vs 9–11/64），但世界模型的候选排序指标在改善
   （selection_score 0.0685 → 0.0534，即离线排序更准），且 H1 依然显著优于贪心
   （8 vs 0，前进 ~2 倍，跌倒 ~2.3 倍少）。
3. **关键负结果**：单纯增大模型容量 + 数据量 + 更新数 + 下层 z 范围，**没有**把绝对
   完成率提上去。下层 ±6 cm 已达标（0 跌倒），说明瓶颈**不在下层能力，也不在上层
   容量/数据量**，而在上层"闭环选点 → 真实执行"之间的动力学可行性缺口（例如紧邻梅花桩
   的高差可达 ~10 cm、窄踏面 + ~3 cm 落足误差导致的失稳，以及急转弯段的 yaw 实现）。

## 下一步方向（供选择，不再盲目扩量）

- 诊断"几何可行候选"与"实际闭环可落脚"的差距：对每个失败点，看所选候选的支撑率、
  高差、横向间距与落足误差的关系；
- 动作接口层面：是否需要在窄桩/急转弯处引入更细的局部连续动作或时序扩展选项；
- 奖励/训练目标层面：用真实执行结果（而非几何代理）主导评分。
